# CGKN current project management

Current project management follows the product authority in `PRODUCT_GOAL.md`,
`MVP_SCOPE.md`, `governance/product_invariants.json`, and
`governance/current_architecture.json`.

The current roadmap is substrate-first:

1. common Component/Block boundary;
2. CapabilityTree composition;
3. Tree-to-DAG compilation;
4. replaceable bounded executors;
5. persistent project state and real tests;
6. smallest-affected-subgraph repair;
7. capability registry and first validated self-growth;
8. project-team views and later promotion capabilities.

The current machine-readable surfaces are:

- `backlog.json` — only active and near-term MVP work;
- `risks.json` — current material architecture and delivery risks;
- `active_iteration.json` — the single active increment;
- `enterprise_experience.json` — a small set of reusable reviewed lessons.

Historical Fixed10, role-driven validation, stress, soak, and old project-studio
records remain in Git history, summaries, or `legacy/pre_mvp_reset/`. They do
not define current priority or readiness.

Management records are support state. They cannot authorize functional success,
formal evidence, packaging, or delivery.
