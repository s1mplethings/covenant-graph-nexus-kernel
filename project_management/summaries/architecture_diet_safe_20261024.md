# Workstream A — Safe Architecture Diet

Workstream A removed only statically proven unused imports/bindings and two exact duplicate capability-builder helpers. It did not alter routing, checkpoint/persistence behavior, Blueprint semantics, acceptance, authority, or public contracts.

The reproducible inventory covers 222 production Python modules. Production LOC fell from 76,461 to 76,438. Internal dependency edges rose from 511 to 512 because both duplicate helpers now reuse the established revision-store implementation; this small structural edge buys a single semantic implementation. File count, module count, public classes/functions, dataclass/schema count, maximum import depth, and wrapper depth are unchanged. Public surface, registry, and schema hashes remain identical to the baseline.

No module was deleted on static-reference evidence alone. Forty-five modules remain `UNCERTAIN` because dynamic registry, MCP, serialization, compatibility, or plugin references can evade static imports. The complete inventory is generated by `scripts/architecture_diet_audit.py`.

Blueprint fields were classified but not changed. The current fixed strong-role path and `FULL_RETRY` evaluation hook remain evidence-gated collapse/move candidates. The Knowledge store/persistence/internalization import cycle belongs to Workstream C; Provider/capability routing helper consolidation belongs to Workstream B.
