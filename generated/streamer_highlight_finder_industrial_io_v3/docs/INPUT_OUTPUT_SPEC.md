# Industrial Input/Output Specification for Game Stream Highlight Analyzer

## Overview
This document defines the industrial input/output specification for the Game Stream Highlight Analyzer project. The tool is designed to identify, score, rank, and export high-impact moments from game streams using multi-source data. It leverages simulated industrial-grade inputs and outputs to ensure modularity, scalability, and usability.

---

## Input Schema

### Input Bundle Path
- **Path**: `data/industrial_input_bundle.json`
- **Description**: Contains raw data from simulated industrial sources, including platform event logs, chat analytics, creator manual marks, public clip metadata, and moderation/ops annotations.

### Input Fields
The input bundle consists of records with the following fields:

| Field Name       | Type               | Description                                                                 |
|------------------|--------------------|-----------------------------------------------------------------------------|
| `sourceId`       | `string`           | Unique identifier for the data source.                                      |
| `sourceType`     | `string`           | Type of source (e.g., "platform_event_log", "chat_analytics").              |
| `origin`         | `string`           | Origin of the data (e.g., "Twitch", "YouTube").                             |
| `trustLevel`     | `integer` (0-100)  | Confidence level in the data's accuracy.                                    |
| `licenseOrAccess`| `string`           | Licensing or access information for the data.                               |
| `fieldsProvided` | `array of strings` | List of fields included in the record.                                      |
| `streamer`       | `string`           | Name of the streamer.                                                       |
| `game`           | `string`           | Name of the game being streamed.                                            |
| `category`       | `string`           | Category of the highlight (e.g., "kill streak", "funny moment").            |
| `timestamp`      | `ISO8601 string`   | Timestamp of the event.                                                     |
| `time`           | `integer` (seconds)| Duration of the event.                                                      |
| `title`          | `string`           | Title of the highlight.                                                     |
| `description`    | `string`           | Description of the highlight.                                               |
| `intensity`      | `integer` (0-100)  | Intensity score based on visual/audio cues.                                 |
| `chatRate`       | `integer`          | Number of chat messages per second during the event.                        |
| `keywords`       | `array of strings` | Keywords extracted from chat or metadata.                                   |
| `viewerSpike`    | `integer`          | Number of viewers gained during the event.                                  |
| `clipSignal`     | `boolean`          | Indicates whether the event was manually clipped by viewers.                |

### Resource Provenance Labels
Each record includes provenance labels to indicate the source and reliability of the data:
- **Simulated Sources**:
  - Platform event logs (e.g., viewer spikes, follower gains).
  - Chat analytics (e.g., keyword spikes, sentiment analysis).
  - Public clip metadata (e.g., timestamps, manual clips).
  - Creator manual marks (e.g., editor or streamer annotations).
  - Moderation/ops annotations (e.g., flagged moments for quality review).

## Output Schema

### Output Path
- **Path**: `data/expected_outputs.json`
- **Description**: Contains the expected outputs generated by the tool, including ranked highlights and export cut lists.

### Output Fields
The output consists of records with the following fields:

| Field Name         | Type               | Description                                                                 |
|--------------------|--------------------|-----------------------------------------------------------------------------|
| `rankedHighlights` | `array of objects` | List of highlights ranked by score.                                         |
| `exportCutList`    | `array of objects` | List of highlights selected for export.                                     |
| `qualityChecks`    | `array of strings` | List of validation checks performed on the data.                            |
| `inputSummary`     | `object`           | Summary of the imported data (e.g., record count, source breakdown).        |

---

## Field Meanings

### Key Fields in Input
- **Streamer**: Identifies the creator of the stream.
- **Game**: Specifies the game being streamed.
- **Category**: Classifies the type of highlight (e.g., "kill streak").
- **Intensity**: Measures the excitement level of the moment.
- **ChatRate**: Indicates audience engagement during the event.
- **Keywords**: Highlights key terms from chat or metadata.
- **ViewerSpike**: Reflects audience growth during the event.

### Key Fields in Output
- **RankedHighlights**: Ordered list of moments based on scoring criteria.
- **ExportCutList**: Final selection of moments for export.
- **QualityChecks**: Ensures data integrity and scoring accuracy.
- **InputSummary**: Provides insights into the imported dataset.

---

## Validation Rules

### Input Validation
1. **Field Completeness**: Ensure all required fields are present in each record.
2. **Data Types**: Validate field types (e.g., `timestamp` must be ISO8601).
3. **Trust Level**: Reject records with `trustLevel` below 50.
4. **Source Type**: Accept only predefined source types (e.g., "platform_event_log").
5. **Minimum Record Count**: Ensure at least 20 records are imported.

### Output Validation
1. **Scoring Accuracy**: Verify that scores align with predefined criteria.
2. **Ranking Order**: Ensure highlights are sorted by score in descending order.
3. **Export Integrity**: Validate that exported records match user-selected criteria.

---

## Edge Cases

### Input Edge Cases
- **Missing Fields**: Handle records with missing optional fields by assigning default values.
- **Invalid Timestamps**: Skip records with improperly formatted timestamps.
- **Low Trust Level**: Exclude records with `trustLevel` below the threshold.

### Output Edge Cases
- **Empty Results**: Display a message if no highlights meet the filtering criteria.
- **Duplicate Records**: Deduplicate highlights based on `timestamp` and `streamer`.
- **Export Errors**: Retry export if file generation fails.

---

## Transformation Process

### Input to Ranked Highlights
1. **Data Ingestion**: Parse and normalize records from the input bundle.
2. **Scoring**: Assign scores based on intensity, chat rate, viewer spikes, and keywords.
3. **Ranking**: Sort records by score in descending order.

### Ranked Highlights to Export Cut List
1. **Filtering**: Apply user-defined filters (e.g., game, streamer, score threshold).
2. **Manual Annotation**: Allow users to add or adjust highlight tags.
3. **Export**: Generate a downloadable JSON file containing the filtered highlights.
