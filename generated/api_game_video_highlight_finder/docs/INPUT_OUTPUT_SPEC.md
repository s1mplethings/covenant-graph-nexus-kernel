# Industrial Input/Output Specification for Streamer Highlight Tool

## Overview

The **Streamer Highlight Tool** is designed to assist game streamers and content creators in automatically identifying highlight segments from a single video file. The tool provides a timeline of highlights and a downloadable clip list, streamlining the process of content creation and management.

## Input Schema

The input to the system is defined in the `data/industrial_input_bundle.json` file. The input schema consists of a collection of records, each representing an event or interaction during a game stream. The schema is as follows:

```json
{
  "records": [
    {
      "sourceId": "string",
      "streamer": "string",
      "game": "string",
      "category": "string",
      "timestamp": "integer",
      "time": "string",
      "title": "string",
      "description": "string",
      "intensity": "float",
      "chatRate": "float",
      "keywords": ["string"],
      "viewerSpike": "boolean",
      "clipSignal": "boolean"
    }
  ]
}
```

### Field Meanings

- **sourceId**: Unique identifier for the source of the record (e.g., event log ID).
- **streamer**: Name of the streamer or content creator.
- **game**: Title of the game being streamed.
- **category**: Category of the content (e.g., gameplay, tutorial).
- **timestamp**: Unix timestamp indicating when the event occurred.
- **time**: Human-readable time format (e.g., "00:05:30").
- **title**: Title of the highlight or event.
- **description**: Detailed description of the event.
- **intensity**: A float value representing the intensity of the event (e.g., 0.0 to 1.0).
- **chatRate**: The rate of chat messages during the event, indicating viewer engagement.
- **keywords**: An array of keywords associated with the event.
- **viewerSpike**: A boolean indicating if there was a spike in viewers during the event.
- **clipSignal**: A boolean indicating if the event is a potential highlight for clipping.

### Source Categories

The input data is simulated and sourced from plausible industrial categories, including:

- **Platform Event Logs**: Logs generated by streaming platforms capturing various events during a stream.
- **Chat Analytics**: Data analyzing viewer interactions and engagement during the stream.
- **Creator Manual Marks**: Manual annotations made by the streamer indicating significant moments.
- **Public Clip Metadata**: Metadata from publicly shared clips that may indicate popular moments.
- **Moderation/Ops Annotations**: Notes from moderators or operations teams regarding significant events.

### Resource Provenance Labels

Each record in the input bundle should include provenance labels to indicate the source of the data. This includes:

- **source_id**: Identifier for the source.
- **source_type**: Type of source (e.g., event log, chat analytics).
- **origin**: Origin of the data (e.g., platform name).
- **trust_level**: Trustworthiness of the data source (e.g., high, medium, low).
- **license_or_access**: Information on the access rights or licenses associated with the data.

## Output Schema

The output of the system is defined in the `data/expected_outputs.json` file. The output schema consists of the following components:

```json
{
  "ranked_highlights": [
    {
      "highlightId": "string",
      "sourceId": "string",
      "timestamp": "integer",
      "title": "string",
      "description": "string",
      "score": "float"
    }
  ],
  "export_cut_list": [
    {
      "highlightId": "string",
      "startTime": "string",
      "endTime": "string",
      "title": "string"
    }
  ],
  "quality_checks": {
    "input_summary": {
      "totalRecords": "integer",
      "validRecords": "integer",
      "invalidRecords": "integer"
    }
  }
}
```

### Output Field Meanings

- **ranked_highlights**: An array of highlights ranked by their significance or score.
  - **highlightId**: Unique identifier for the highlight.
  - **sourceId**: Identifier for the source record.
  - **timestamp**: Unix timestamp of the highlight.
  - **title**: Title of the highlight.
  - **description**: Description of the highlight.
  - **score**: Score indicating the significance of the highlight.

- **export_cut_list**: An array of highlights ready for export as clips.
  - **highlightId**: Unique identifier for the highlight.
  - **startTime**: Start time of the clip.
  - **endTime**: End time of the clip.
  - **title**: Title of the clip.

- **quality_checks**: Summary of the input data quality.
  - **input_summary**: Contains counts of total, valid, and invalid records.

## Validation Rules

The system must adhere to the following validation rules:

1. **Minimum Record Count**: The input bundle must contain at least 20 records.
2. **Field Validation**: Each record must contain all required fields with appropriate data types.
3. **Timestamp Validation**: Timestamps must be valid Unix timestamps.
4. **Score Calculation**: The scoring algorithm must be applied consistently to rank highlights based on intensity, chat rate, and viewer spikes.

## Edge Cases

The system should handle the following edge cases:

- **Insufficient Records**: If fewer than 20 records are provided, the system should return an error indicating the need for more data.
- **Invalid Data Types**: If any field contains an invalid data type, the system should log the error and skip that record.
- **Duplicate Records**: The system should identify and handle duplicate records, either by merging or discarding them based on predefined rules.

## Processing Logic

The application processes the input bundle to generate ranked highlights and an export cut list through the following steps:

1. **Data Import**: The input data is imported and parsed from the JSON file.
2. **Validation**: The input data is validated against the defined rules.
3. **Scoring**: Each record is scored based on its intensity, chat rate, and viewer spikes.
4. **Highlight Ranking**: The records are sorted based on their scores to identify the top highlights.
5. **Export Preparation**: The top highlights are formatted into an export cut list for easy downloading.

## Testing

The functionality of the input/output processing will be validated through the `tests/industrial_io_smoke_test.js` file. This test will ensure that:

- The input schema is correctly parsed and validated.
- The output schema matches the expected structure.
- The scoring and ranking logic produces consistent results.

## Conclusion

This industrial input/output specification outlines the necessary components for the Streamer Highlight Tool, detailing the input and output schemas, field meanings, validation rules, and processing logic. By adhering to these specifications, the tool will effectively assist game streamers and content creators in managing their highlight clips efficiently.
