# TEST_PLAN.md

## Overview
This document outlines the test plan for the **Game Stream Highlight Detector** project. The tests are designed to validate the functionality, usability, and performance of the application. The following features will be tested:

1. Import functionality
2. Scoring logic
3. Sorting logic
4. Filters (streamer, game, category, score)
5. Manual marker functionality
6. Export functionality
7. LocalStorage persistence
8. Console error handling

---

## Test Cases

### 1. Import Functionality
**Objective:** Verify that the application can successfully import live stream event data.

- **Test Case 1.1:** Import JSON file via file input
  - **Steps:**
    1. Select a valid JSON file using the file input.
    2. Click the "Import" button.
  - **Expected Result:** Data is parsed, normalized, and displayed in the results panel.

- **Test Case 1.2:** Import JSON data via textarea
  - **Steps:**
    1. Paste valid JSON data into the textarea.
    2. Click the "Import" button.
  - **Expected Result:** Data is parsed, normalized, and displayed in the results panel.

- **Test Case 1.3:** Handle invalid JSON input
  - **Steps:**
    1. Import a file or paste data with invalid JSON format.
  - **Expected Result:** An error message is displayed, and no data is imported.

---

### 2. Scoring Logic
**Objective:** Ensure that records are scored correctly based on the scoring function.

- **Test Case 2.1:** Verify scoring of imported records
  - **Steps:**
    1. Import a dataset with known scoring criteria.
  - **Expected Result:** Each record is assigned a score based on the scoring function.

- **Test Case 2.2:** Validate scoring accuracy
  - **Steps:**
    1. Compare scores generated by the app with manually calculated scores.
  - **Expected Result:** Scores match the expected values.

---

### 3. Sorting Logic
**Objective:** Validate that records are sorted in descending order of scores.

- **Test Case 3.1:** Verify default sorting
  - **Steps:**
    1. Import a dataset.
  - **Expected Result:** Records are displayed in descending order of scores.

- **Test Case 3.2:** Verify sorting after manual marker addition
  - **Steps:**
    1. Add a new record using the manual marker form.
  - **Expected Result:** The new record is inserted into the correct position based on its score.

---

### 4. Filters
**Objective:** Ensure that filters for streamer, game, category, and score work as expected.

- **Test Case 4.1:** Filter by streamer
  - **Steps:**
    1. Enter a streamer's name in the filter form.
    2. Apply the filter.
  - **Expected Result:** Only records matching the streamer's name are displayed.

- **Test Case 4.2:** Filter by game
  - **Steps:**
    1. Enter a game's name in the filter form.
    2. Apply the filter.
  - **Expected Result:** Only records matching the game's name are displayed.

- **Test Case 4.3:** Filter by category
  - **Steps:**
    1. Select a category from the filter form.
    2. Apply the filter.
  - **Expected Result:** Only records matching the selected category are displayed.

- **Test Case 4.4:** Filter by score range
  - **Steps:**
    1. Enter a minimum and/or maximum score in the filter form.
    2. Apply the filter.
  - **Expected Result:** Only records within the specified score range are displayed.

---

### 5. Manual Marker Functionality
**Objective:** Verify that users can manually add records to the dataset.

- **Test Case 5.1:** Add a new record
  - **Steps:**
    1. Fill out the manual marker form with valid data.
    2. Submit the form.
  - **Expected Result:** The new record is added to the dataset and displayed in the results panel.

- **Test Case 5.2:** Handle invalid input
  - **Steps:**
    1. Submit the manual marker form with missing or invalid data.
  - **Expected Result:** An error message is displayed, and the record is not added.

---

### 6. Export Functionality
**Objective:** Ensure that the export functionality works as expected.

- **Test Case 6.1:** Export filtered results
  - **Steps:**
    1. Apply filters to the dataset.
    2. Click the "Export" button.
  - **Expected Result:** A JSON file containing the filtered results is downloaded.

- **Test Case 6.2:** Validate exported data
  - **Steps:**
    1. Open the exported JSON file.
    2. Verify the contents match the filtered dataset.
  - **Expected Result:** Exported data matches the current filtered dataset.

---

### 7. LocalStorage Persistence
**Objective:** Verify that data is persisted in localStorage and restored on page reload.

- **Test Case 7.1:** Save data to localStorage
  - **Steps:**
    1. Import a dataset.
    2. Reload the page.
  - **Expected Result:** The dataset is restored from localStorage.

- **Test Case 7.2:** Clear localStorage
  - **Steps:**
    1. Clear the dataset using the app's controls.
    2. Reload the page.
  - **Expected Result:** No data is restored.

---

### 8. Console Error Handling
**Objective:** Ensure that no unexpected errors are logged to the console.

- **Test Case 8.1:** Monitor console during normal usage
  - **Steps:**
    1. Perform common tasks (import, filter, add manual marker, export).
  - **Expected Result:** No errors are logged to the console.

- **Test Case 8.2:** Monitor console during edge cases
  - **Steps:**
    1. Perform edge case actions (e.g., import invalid JSON, submit incomplete manual marker form).
  - **Expected Result:** Errors are handled gracefully, and meaningful messages are displayed to the user.

---

## Testing Tools
- **Browser:** Chrome, Firefox, Edge
- **Testing Library:** Jest (for unit tests), Cypress (for end-to-end tests)
- **Sample Data:** `data/sample_events.json`

- The application must meet the functional requirements outlined in the project plan.
- No critical bugs or usability issues should remain unresolved.

- **Timeline:** 2 weeks
- **Reporting:** Document test results and issues in a shared tracking system.

This test plan ensures that the **Game Stream Highlight Detector** meets its functional, usability, and performance goals. Successful execution of this plan will validate the application's readiness for release.
